# Участие в разработке

Будем рады сообщениям об ошибках, небольшим исправлениям, тестам и pull request.

## Перед созданием Issue

- Проверьте, воспроизводится ли проблема на последнем релизе или в `main`.
- Укажите версию приложения, ОС, версию Python (если запускали из исходников), команду или действие и полный текст ошибки.
- По возможности приложите минимальный воспроизводимый пример.
- Не загружайте образы прошивок с персональными данными, приватными ключами, токенами или файлами, распространение которых вам не разрешено.

## Перед Pull Request

1. Создайте отдельную ветку для изменений.
2. Добавьте тесты новой логики и ошибочных сценариев.
3. Запустите полный набор тестов:

   ```bash
   python -m unittest discover -s tests -v
   ```

4. Обновите оба README, если меняется пользовательское поведение или CLI-параметры.
5. Обновите английскую и русскую документацию и историю изменений.
6. Не добавляйте сторонние зависимости без обоснованной необходимости. CLI должен оставаться на стандартной библиотеке.
7. GUI должен использовать `sparse_to_raw.py`; не добавляйте второй парсер Sparse или отдельную реализацию контрольных сумм.

## Принципы проекта

- Повреждённые данные должны приводить к понятной ошибке и ненулевому коду возврата CLI.
- Ошибка или отмена конвертации не должны повреждать существующий выходной файл.
- Обработка образов должна быть потоковой, без загрузки всего файла в память.
- Приложение работает только с файлами; не добавляйте прошивку телефонов или запись в разделы устройств.
