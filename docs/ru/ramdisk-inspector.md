# Android Ramdisk Inspector

`sparse-to-raw` умеет просматривать CPIO-архивы внутри Android boot-образов или в виде отдельных ramdisk-файлов, а также безопасно извлекать выбранные записи. Команды CLI — `ramdisk-info` и `ramdisk-extract`; диалог GUI находится в меню **«Инструменты» → Ramdisk Inspector**.

## Поддерживаемые входные образы

- Legacy и generic Android boot-образы, поддерживаемые Boot Image Inspector, включая `boot.img`, `recovery.img` и `init_boot.img`.
- `vendor_boot` v3/v4. Если в `vendor_boot` v4 имеется несколько фрагментов vendor ramdisk, нужно выбрать один по индексу с нуля. Если фрагмент только один, он выбирается автоматически.
- Отдельные несжатые или сжатые CPIO-архивы.

Для `vendor_boot` v4 выбранный фрагмент читается по диапазону, указанному в таблице vendor ramdisk. Фрагменты анализируются по отдельности; программа не объединяет их в искусственное общее представление файловой системы. Назначение таблицы фрагментов v4 описано в документации AOSP [vendor boot partitions](https://source.android.com/docs/core/architecture/partitions/vendor-boot-partitions).

## Поддерживаемые форматы сжатия и архивов

Инспектор распознаёт и распаковывает:

- Несжатый CPIO `newc` (`070701`) и CPIO с CRC `070702`.
- gzip, bzip2, XZ, LZMA-alone.
- LZ4 frame и LZ4 legacy frame.

Контрольная сумма CPIO `070702` проверяется. В `newc` нет контрольной суммы данных каждого файла. Поддерживаются последовательные CPIO-архивы и нулевое заполнение между ними. При извлечении более поздние архивы перекрывают ранние записи с тем же путём: сохраняется последнее вхождение имени.

Сигнатуры Zstandard и LZO/lzop распознаются, но распаковка этих форматов не включена в сборку без сторонних зависимостей. CLI не устанавливает и не запускает внешние утилиты распаковки.

## Анализ через CLI

Просмотр CPIO внутри boot-образа:

```powershell
py sparse_to_raw.py ramdisk-info boot.img
py sparse_to_raw.py ramdisk-info init_boot.img --json-report init-ramdisk.json
```

Просмотр конкретного фрагмента `vendor_boot` v4 (индексация начинается с нуля):

```powershell
py sparse_to_raw.py ramdisk-info vendor_boot.img --fragment-index 1
```

Просмотр отдельного сжатого архива:

```powershell
py sparse_to_raw.py ramdisk-info vendor-ramdisk.cpio.gz
```

Отчёт содержит тип входного образа и выбранной секции/фрагмента, формат сжатия, форматы CPIO, количество архивов и записей, количество файлов/каталогов/символических ссылок, общий размер файлов, предупреждения, а также путь, тип, размер, режим, UID/GID, время, сведения об inode/hardlink и статус checksum для каждой записи. `--json-report FILE` сохраняет инвентаризацию в JSON. Существующие отчёты защищены от перезаписи, если не указан `--force`.

## Извлечение всех записей или выбранных путей

Извлечь выбранный ramdisk в новый каталог:

```powershell
py sparse_to_raw.py ramdisk-extract boot.img --output-dir ramdisk-files
```

Извлечь только отдельные записи. Параметр `--include` можно повторять; выбор каталога включает его содержимое:

```powershell
py sparse_to_raw.py ramdisk-extract boot.img --output-dir selected --include init --include etc
```

Для `vendor_boot` v4 с несколькими фрагментами:

```powershell
py sparse_to_raw.py ramdisk-extract vendor_boot.img --fragment-index 1 --output-dir recovery-ramdisk
```

Лимит распакованных данных по умолчанию — 512 МиБ. При необходимости его можно изменить:

```powershell
py sparse_to_raw.py ramdisk-info boot.img --max-unpacked-mib 1024
```

Распакованный CPIO-поток временно сохраняется в файл и анализируется с ограниченным использованием памяти. По умолчанию допускается не более 200 000 записей CPIO. При извлечении создаются только обычные файлы и каталоги. Существующий непустой каталог защищён от изменений; `--force` разрешает объединение с ним и замену совпадающих файлов. JSON-отчёт можно сохранить параметром `--json-report`.

## Безопасность извлечения

- Абсолютные пути, переходы к родительскому каталогу (`..`), синтаксис дисков/альтернативных потоков Windows, зарезервированные имена устройств и другие небезопасные пути пропускаются и попадают в отчёт.
- Символические ссылки не создаются как реальные ссылки файловой системы. Их цели записываются в `SYMLINKS.txt`.
- Узлы устройств, сокеты, FIFO и другие специальные записи не создаются. Они перечисляются в `SPECIAL_FILES.txt`.
- Записи CPIO с hardlink получают одинаковое содержимое, но извлекаются как отдельные файлы; связи hardlink файловой системы не восстанавливаются.
- Биты прав обычных файлов применяются, если это допускает платформа. Владелец, временные метки, права каталогов, SELinux labels, capabilities и прочие метаданные файловой системы не восстанавливаются.
- Исходный boot-образ или отдельный CPIO-файл не изменяется.

## GUI

Откройте **«Инструменты» → Ramdisk Inspector**, выберите boot-образ или отдельный CPIO-архив и нажмите **«Просмотреть содержимое»**. Для `vendor_boot` v4 с несколькими фрагментами включите выбор фрагмента и укажите индекс с нуля. Таблица показывает путь CPIO, тип записи, размер, режим и статус checksum. Выберите одну или несколько строк и нажмите **«Извлечь выбранное»** либо используйте **«Извлечь всё»**. При выборе каталога извлекаются и вложенные записи.

Распаковка, анализ и извлечение выполняются в рабочем потоке. Операцию можно отменить; лимит распаковки настраивается. **«Экспорт JSON»** сохраняет инвентаризацию. Изменение пути источника или выбранного фрагмента vendor ramdisk сбрасывает предыдущий список, чтобы пути из одного архива нельзя было случайно применить к другому.

## Ограничения

- Zstandard и LZO/lzop распознаются, но не распаковываются в реализации без сторонних зависимостей.
- Поддерживается чтение CPIO newc/crc; это не универсальный менеджер архивов и не средство пересборки boot-образов.
- Программа не создаёт символические ссылки и специальные узлы устройств, не восстанавливает владельца/SELinux-метаданные и не гарантирует, что извлечённые файлы образуют загрузоспособный ramdisk.
- Лимит распаковки и максимальное число CPIO-записей — защитные ограничения, а не оценка доступной памяти устройства.
