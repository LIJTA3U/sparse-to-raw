# Поддержка XML Qualcomm QFIL

CLI умеет анализировать манифесты Qualcomm Firehose/QFIL `rawprogram*.xml` и `patch*.xml`, находить связанные бинарные файлы и собирать по одному RAW-образу на каждую физическую партицию (LUN).

## Анализ прошивки

```bat
py sparse_to_raw.py qfil-analyze rawprogram0.xml --patch-xml patch0.xml --search-dir .
```

Можно передать несколько `rawprogram*.xml`, а параметры `--patch-xml` и `--search-dir` повторять:

```bat
py sparse_to_raw.py qfil-analyze rawprogram0.xml rawprogram1.xml --patch-xml patch0.xml --patch-xml patch1.xml --search-dir . --json-report qfil-analysis.json
```

Отчёт содержит тип операции, метку раздела, LUN, секторные координаты, размер сектора, имя исходного файла, результат поиска, сводку разделов и атрибуты patch-операций. Сначала файл ищется относительно XML-манифеста, затем папка манифеста и каждый каталог `--search-dir` рекурсивно сканируются по имени файла. Если найдено несколько совпадений, результат помечается как неоднозначный — программа не выбирает один файл наугад.

## Сборка RAW-образов

```bat
py sparse_to_raw.py qfil-build rawprogram0.xml --patch-xml patch0.xml --search-dir . --output-dir raw-output --json-report qfil-build.json
```

Для каждого LUN создаётся отдельный файл: `physical_partition_0.raw`, `physical_partition_1.raw` и т. д. Для размещения данных используются `SECTOR_SIZE_IN_BYTES`, `start_sector`, `num_partition_sectors`, `file_sector_offset`, `physical_partition_number`, `filename` и флаг `sparse`. Обычные RAW-файлы копируются ограниченными блоками. Источник с `sparse="true"` раскрывается прямо во временный итоговый RAW-образ и проходит стандартную проверку структуры Sparse и контрольных сумм — промежуточный распакованный RAW не создаётся.

Выходной образ изначально состоит из нулевых байтов. Поэтому области `DONT_CARE` и диапазоны `<erase>` остаются нулевыми; если пересечения явно разрешены, erase также применяется в порядке XML-операций. Перед публикацией выходные файлы создаются во временной области, существующие результаты защищены от перезаписи без `--force`, а свободное место проверяется заранее.

## Секторные выражения и пересечения

В некоторых манифестах используются координаты относительно конца накопителя, например `NUM_DISK_SECTORS-33`. Сам размер накопителя из этого выражения определить нельзя, поэтому нужно передать число секторов для соответствующего LUN:

```bat
py sparse_to_raw.py qfil-build rawprogram0.xml --search-dir . --output-dir raw-output --disk-sectors 0=61071360
```

Для каждого LUN с выражением относительно конца накопителя укажите отдельный параметр `--disk-sectors LUN=COUNT`. Значение задаётся в секторах, а не в байтах.

Пересечения диапазонов записи и стирания по умолчанию запрещены. После проверки манифеста намеренные пересечения можно разрешить через `--allow-overlap`. В таком режиме операции выполняются в порядке XML, а более поздние операции заменяют ранее записанные байты.

## Безопасность patch XML

Файлы `patch*.xml` разбираются и включаются в анализ и JSON-отчёты, но их значения **не применяются** к собранным RAW-образам. Инструкции QFIL patch могут зависеть от конкретного Firehose-программатора, геометрии устройства и других параметров сборки. Применение значений без этого контекста может привести к некорректному образу. Используйте отчёт patch как список для проверки; для модификаций, специфичных для устройства, ориентируйтесь на исходный пакет производителя и соответствующий программатор.

## Код завершения и зависимости

- `0` — анализ XML или сборка RAW завершились успешно.
- `2` — ошибка XML, ненайденный/неоднозначный файл, неподдерживаемое секторное выражение, пересечение диапазонов, нехватка места или ошибка ввода-вывода.

Поддержка QFIL использует только стандартную библиотеку Python. Для необязательного GUI по-прежнему требуется PySide6, CLI не требует сторонних библиотек.
