# Контрольный список релиза v0.6.0

Этот список разделяет проверку исходников, сборку Windows-пакетов и публикацию GitHub Release. Не объявляйте v0.6.0 стабильным, пока не пройдены все обязательные этапы.

## 1. Проверка исходников кандидата релиза

Из корня репозитория в Windows выполните:

```powershell
py -m compileall -q .
py -m unittest discover -s tests -v
py tests\gui_smoke_tests.py
py sparse_to_raw.py --version
py sparse_to_raw.py --help
```

Ожидаемая версия: `sparse-to-raw v0.6.0-rc1`.

## 2. Отправка кандидата и проверка CI

Отправьте проверенные исходники в `main` и убедитесь, что успешно завершились workflow:

- `Tests`: Python 3.10–3.14 на Windows и Linux.
- `GUI smoke tests`: GUI-тесты PySide6 на Windows и Linux.

Исправьте все ошибки до создания кандидата релиза.

## 3. Сборка Windows-пакетов через GitHub Actions

Создайте GitHub prerelease с тегом `v0.6.0-rc1` на основе проверенного коммита. Публикация prerelease запускает `.github/workflows/build-windows-release.yml`.

Workflow должен собрать и приложить три файла:

- `sparse-to-raw.exe` — автономная CLI.
- `sparse-to-raw-gui.exe` — автономная GUI.
- `sparse-to-raw-gui-windows.zip` — GUI-пакет с папкой и библиотеками.

Перед сборкой workflow запускает тесты и компиляцию Python, проверяет упакованный CLI и запускает GUI `--self-test` для обоих вариантов GUI с удалёнными путями Python из `PATH`.

Скачайте все три файла из prerelease и проверьте их на чистой Windows-системе или в учётной записи без Python. GUI ZIP необходимо распаковывать целиком; нельзя отделять EXE от папки библиотек.

## 4. Переход к стабильному v0.6.0

После проверки RC:

1. Измените `APP_VERSION` в `sparse_to_raw.py` с `v0.6.0-rc1` на `v0.6.0`.
2. Добавьте финальную запись `v0.6.0` в начало `CHANGELOG.md`, `docs/en/changelog.md` и `docs/ru/changelog.md`.
3. Обновите ссылки в README и инструкциях установки на стабильный релиз `v0.6.0`.
4. Повторно запустите полный набор тестов и GUI-команды, создайте коммит и отправьте его в GitHub.
5. Создайте и отправьте тег `v0.6.0` именно на этом проверенном коммите, затем опубликуйте GitHub Release. Windows workflow автоматически соберёт и приложит три пакета.
6. Скачайте опубликованные стабильные файлы и проверьте их запуск до объявления релиза.

## 5. Чистота релиза

- Убедитесь, что ZIP содержит исходники, документацию, ресурсы, тесты и workflows, но не содержит пользовательских файлов прошивок, RAW-дампов, Sparse-образов, Python-кэша и локальных build-артефактов.
- Рассчитайте SHA-256 для всех опубликованных файлов и добавьте суммы в описание релиза.
- Сохраните предупреждение по безопасности: программа обрабатывает файлы и не прошивает устройства; QFIL patch-команды только отображаются в отчётах и не исполняются.
