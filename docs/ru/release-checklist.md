# Контрольный список подготовки стабильного релиза v0.7.0

Используйте этот список для финального стабильного релиза v0.7.0. Все проверки должны выполняться на точном коммите, из которого будет создан релизный тег. Не создавайте тег, пока обязательные проверки не завершены.

## 1. Проверка исходников и версии

Из корневого каталога проекта в Windows выполните:

```powershell
py -m compileall -q .
py -m unittest discover -s tests -p "test_*.py" -v
py tests\gui_smoke_tests.py
py sparse_to_raw.py --version
py sparse_to_raw.py --help
```

Релизный коммит должен выводить `sparse-to-raw v0.7.0`. Перед финальным запуском тестов и сборки константа `APP_VERSION` должна быть установлена в `v0.7.0`. Обе истории изменений и оба файла Release Notes должны описывать одно и то же содержимое релиза.

Проверьте наличие в справке интегрированных команд: `qfil-analyze`, `qfil-validate`, `qfil-build`, `super-info`, `super-extract`, `vbmeta-info`, `boot-info`, `ramdisk-info`, `ramdisk-extract`, `validate`, `compare` и `raw-to-sparse`.

В репозитории должны присутствовать три небольшие синтетические фикстуры Super Image из `tests/fixtures/`: `super_multi_extent.img`, `expected_system.img` и `expected_vendor.img`. Это тестовые данные, а не дампы прошивок.

## 2. Проверка CI и сборки релиза

Убедитесь, что успешно завершились GitHub Actions:

- Основные тесты на Python 3.10–3.14 в Windows и Linux.
- GUI smoke-тесты с PySide6 в Windows и Linux.
- Windows workflow сборки: в том числе проверки упакованных CLI-команд QFIL и Super Image, а также GUI `--self-test` при удалённых из `PATH` каталогах Python.

В релиз должны попасть `sparse-to-raw.exe`, `sparse-to-raw-gui.exe`, `sparse-to-raw-gui-windows.zip` и `SHA256SUMS.txt`.

## 3. Проверка скачанных Windows-пакетов

- Запустите упакованный CLI с `--version` и `--help`, а также `qfil-validate --help` и `super-info --help`.
- Запустите автономный GUI EXE.
- Полностью распакуйте GUI ZIP и запустите приложение из распакованной папки. Не нарушайте структуру каталогов пакета.
- Проверьте GUI под учётной записью или на компьютере Windows без установленного Python.
- Откройте Ramdisk Inspector и сравните два текстовых конфигурационных файла, например `fstab.mt6762` и `fstab.mt6765`.
- Сверьте каждый скачанный файл с `SHA256SUMS.txt`.

## 4. Область совместимости и известные ограничения

Конвертер Sparse → RAW побайтно сравнивался с AOSP `simg2img.exe` на двух реальных заводских Sparse-образах: `super.img` Blackview и `userdata_exp.ai.img` Google Pixel. Результаты совпали. Это ограниченная выборка, а не всеобъемлющая сертификация совместимости со всеми генераторами Sparse и прошивками.

Super Image Inspector проверялся на RAW- и заводском Sparse-образах `super.img` Blackview, а также на синтетической фикстуре с несколькими extents. Результаты извлечения через CLI и GUI совпали по SHA-256. Поддерживаются версии LP metadata 10.0–10.2. Для извлечения linear extents должны ссылаться на block device с индексом `0`; многобразные retrofit-конфигурации и произвольные наборы `super_*` не поддерживаются.

В документации необходимо сохранять и другие важные ограничения:

- QFIL patch-инструкции разбираются и попадают в отчёт, но не исполняются.
- AVB / VBMeta Inspector не проверяет RSA-подпись, доверие к ключу или rollback state устройства.
- Boot Image Inspector показывает структуру и подсказки о форматах, но не распаковывает kernel/ramdisk и не проверяет AVB-подписи.
- Ramdisk Inspector распознаёт Zstandard и LZO/lzop, но не распаковывает их в сборке без дополнительных зависимостей. Символические ссылки и специальные узлы файловой системы заносятся в манифест, но не создаются при извлечении.

## 5. Безопасность и чистота релиза

- Не включайте в исходные архивы дампы прошивок, пользовательские `.img` / `.raw` / `.sparse`, локальные результаты сборки и Python-кэши. В `tests/fixtures/` оставляйте только три небольшие синтетические фикстуры.
- Сохраняйте предупреждение, что приложение работает с файлами и не прошивает устройства и не взаимодействует с подключёнными телефонами.
- Перед использованием результатов в рабочих сценариях с прошивками независимо проверяйте критически важные файлы.
- Установите `APP_VERSION` в `v0.7.0`, обновите ссылки README и CHANGELOG, создайте тег с точного проверенного коммита, опубликуйте GitHub Release и проверьте приложенные артефакты и контрольные суммы.
