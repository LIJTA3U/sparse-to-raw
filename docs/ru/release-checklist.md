# Контрольный список проверки релиза v0.6.0

Список фиксирует заключительные проверки стабильного релиза v0.6.0 и может использоваться повторно при выпуске исправлений.

## 1. Проверка версии и исходников

Из корневого каталога репозитория в Windows выполните:

```powershell
py -m compileall -q .
py -m unittest discover -s tests -v
py tests\gui_smoke_tests.py
py sparse_to_raw.py --version
py sparse_to_raw.py --help
```

Ожидаемая версия: `sparse-to-raw v0.6.0`.

## 2. Проверка CI и релизной сборки

Убедитесь, что успешно завершились GitHub Actions:

- Основные тесты на Python 3.10–3.14 в Windows и Linux.
- GUI smoke-тесты с PySide6 в Windows и Linux.
- Windows workflow сборки, включая проверку `--version` / `--help` упакованной CLI и GUI `--self-test` с удалёнными путями Python из `PATH`.

Релизный workflow должен приложить `sparse-to-raw.exe`, `sparse-to-raw-gui.exe`, `sparse-to-raw-gui-windows.zip` и `SHA256SUMS.txt`.

## 3. Проверка скачанных Windows-пакетов

- Запустите CLI с параметрами `--version` и `--help`.
- Запустите автономный GUI EXE.
- Полностью распакуйте GUI ZIP и запустите приложение из распакованной папки. Не нарушайте структуру каталогов пакета.
- Проверьте работу на компьютере или учётной записи Windows без установленного Python.
- Сверьте каждый скачанный файл с `SHA256SUMS.txt`.

## 4. Объём проверки совместимости

Побайтное сравнение с `simg2img.exe` выполнено на двух реальных Android Sparse-образах: `super.img` (около 3,6 ГБ) из заводской прошивки Blackview и `userdata_exp.ai.img` (около 6,83 ГБ) из заводской прошивки Google Pixel. Это ограниченная выборка. Контейнеры Android Dynamic Partitions `super` и произвольные многокомпонентные наборы `super_*` этой проверкой не охвачены; программа не разбирает их метаданные Dynamic Partitions. См. [обсуждение 4PDA о десятифайловой структуре `super` Vivo V70 Elite](https://4pda.to/forum/index.php?showtopic=496786&st=5460).

## 5. Безопасность и чистота релиза

- Не включайте в исходные архивы дампы прошивок, `.img`, `.raw`, `.sparse`, `.simg`, локальные build-файлы и кэши.
- Сохраняйте предупреждение, что приложение работает с файлами и не прошивает устройства.
- Сохраняйте предупреждение, что QFIL patch-команды только отображаются в отчётах и не исполняются.
- Для выпуска исправления обновите `APP_VERSION`, changelog, ссылки README, создайте тег с проверенного коммита и проверьте новые опубликованные артефакты.
