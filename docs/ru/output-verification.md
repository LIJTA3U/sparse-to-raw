# Проверка выходного RAW

Проверка повторным чтением добавлена в ходе разработки v0.5.0 и входит в опубликованную ветку релизов v0.5.0, а также в кандидат релиза v0.6.0 и релизную ветку.

## Что именно проверяется

После разбора Sparse-входа и проверки применимых контрольных сумм чанков и образа конвертер закрывает и сбрасывает временный RAW-файл на диск. Если проверка результата включена, программа:

1. Проверяет, что временный результат является обычным файлом ожидаемого логического RAW-размера.
2. Повторно читает его ограниченными блоками по 1 МиБ.
3. Вычисляет SHA-256 по фактически прочитанным байтам временного файла.
4. Сравнивает этот хеш с SHA-256 ожидаемого логического RAW-содержимого, накопленным при раскрытии Sparse.
5. Проверяет, что идентификатор файла, размер и время изменения не изменились во время повторного чтения.
6. Атомарно публикует выходной файл только после успешного прохождения всех проверок.

Таким образом проверяются фактические байты временного RAW, а не только исходный Sparse или успешное завершение вызовов записи. Это всё же не гарантирует защиту от последующего повреждения накопителя, контроллера или файловой системы после завершения программы.

## Использование CLI

```bash
python sparse_to_raw.py input_sparse.img output_raw.img --verify-output
python sparse_to_raw.py --merge-parts part.0 part.1 --output merged_raw.img --verify-output
```

Параметр можно использовать вместе с `--json-report`. В JSON появляется объект `output_verification` с полями `passed`, `method`, ожидаемый и фактический размеры, ожидаемый и фактический SHA-256, число проверенных байтов и длительность. `--verify-output` предназначен для операций, создающих RAW-файл; его нельзя использовать вместе с `--info` или `--verify-only`.

## Использование GUI

В главном окне конвертации, очереди задач и диалоге «Объединить Sparse» есть параметр **«Проверять RAW после записи»**. В текущей ветке разработки он включён по умолчанию, а выбранное состояние сохраняется вместе с остальными настройками GUI.

## Производительность и место на диске

Проверка выполняет дополнительное последовательное чтение всего временного RAW-файла. Поэтому увеличиваются дисковая нагрузка и время операции, особенно для образов размером в несколько гигабайт. Предварительная оценка места учитывает staging-файл; проверка повторно использует его и не создаёт вторую полную копию RAW.

## Ошибки и отмена

Несовпадение размера, ошибка чтения, несовпадение SHA-256 или отмена не позволяют сохранить временный результат в качестве конечного файла. Временный файл удаляется, а уже существующий выходной файл не заменяется.

## Чего эта проверка не делает

- Она не сравнивает хеш сжатого Sparse-файла с хешем RAW: это разные представления данных.
- Она не заменяет проверку заголовка Sparse, CRC32 чанков и общей контрольной суммы образа.
- Она не проверяет конечный файл после атомарного сохранения; проверяется временный файл непосредственно перед публикацией.
